What Sidekick is, what it has become, and how to strip it back to the real POC.

This report was prepared from the repository as it exists in E:\projects\SideKick. It uses the local build plan, phase reviews, docs, migrations, Flutter/Dart source, Android native source, and tests. The repo has uncommitted work; this report does not assume those changes are final.

Current Reality

The app is no longer a small POC. It contains foundations, auth, local-first sync, native Android audio capture, Gemini capture decomposition, inbox triage, auto-commit tasks, habits, Fresh Start, Done list, persona copy, goals data, reminders data, places data, and settings for capture permissions.

Main Drift

The planned product expanded into an ADHD companion platform: capture, inbox, habits, focus sessions, blocking, reminders, geofencing, goals, settings, behavioural events, and future insights. The smart location-reminder POC is still mostly unbuilt.

Recommended Reset

Keep the foundation, auth, local DB, profile/context, places/reminders schema, and a thin AI creation flow. Freeze or remove habits, focus, app blocking, goal sage, Done list, reward systems, and broad capture decomposition until the reminder POC works on-device.

Executive Read

The core feature you now care about, smart location-aware reminders plus an AI with life context, is not the current center of gravity in the built app. The built center is voice capture → Gemini extraction → inbox/task/habit/goal materialization, with habits as the most developed user-facing daily-driver surface.

The project has a strong technical foundation, but it has also absorbed too many product directions before proving the core POC. The build plan explicitly scoped twelve phases: shell, schema, sync/auth, native capture, AI inbox, habits, time reminders, focus sessions, Android app blocking, context intelligence/geofences, settings, iOS blocking, hardening. That is a full personal operating system, not a single-feature POC.

The pieces most relevant to your desired POC already exist as groundwork: offline-first database, profile preferences, places/reminders schema and repositories, behavioural event log, Gemini transport, persona language preference, and enough capture/AI infrastructure to turn natural language into structured drafts. The missing pieces are the actual product: geofence runtime, background location permissions, reminder scheduling/actions, a place/reminder UI, an AI context layer that reads life context, and a narrow UX around “remind me at the right place/time.”

My recommendation: stop building new companion features, fork a “POC mode” product definition, and spend the next slice only on creating, firing, and learning from smart reminders. The current capture/habits/focus machinery should be treated as optional infrastructure, not the app.

Product Meaning

The intended product is an “offline-first analog companion” for ADHD-like executive friction. It started with fast capture and gentle habit support, but the plan grew into a broad assistant: capture thoughts, decompose them, sort them, support habits, run focus sessions, block apps, fire reminders, understand location, infer next actions, and eventually use events for insights.

The requirement tangle comes from pulling future context-intelligence and companion ideas into earlier layers. The schema and docs are preparing for goals, reminders, places, app blocking, focus sessions, and behavioural analytics before the core reminder loop has been proven.

How The Current App Is Built

Runtime Shape

main.dart initializes Supabase and capture notifications/permissions, then runs SidekickApp.

SidekickApp watches the active theme, sync engine, capture owner binding, auto-commit notifications, and capture processing service. It uses MaterialApp.router with a CaptureOverlayHost wrapper.

go_router gates navigation through Splash, Login, Onboarding, then the shell.

Data Shape

Drift tables mirror Supabase migrations 0001, 0002, and local migration state for capture decomposition from 0004.

Every syncable local row has dirty and synced_at. Cloud tables keep created_at, updated_at, and deleted_at.

Feature code depends on repository interfaces; Drift and Supabase stay in data/core layers.

Capture Pipeline

Android volume key gesture → AccessibilityService → ForegroundService recorder → NativeCaptureStore pending event → Flutter method channel → CapturesRepository row → CaptureProcessingService → Gemini → proposed items → inbox review or auto-commit.

The design priority is durability: audio bytes hit disk before network or AI processing.

AI Shape

The current AI boundary is not a general assistant. It is mostly GeminiClient.analyzeCaptureAudio(File), returning structured capture analysis.

Persona generation exists for short habit/Fresh Start copy, but there is no conversation table, no message history, no context-retrieval service, no TTS, and no AI chat surface.

Current Data Model, In Plain English

  • profiles: who the user is in app terms: language, theme, preferences JSON.
  • captures: raw audio/thought events and AI draft output. This is the audit trail.
  • tasks, notes, habits, goals: typed things created from captures or manually.
  • habit_completions: immutable record of habit wins.
  • places: named lat/lng/radius anchors for future geofence reminders.
  • reminders: scheduled or geofence reminder definitions, not yet a firing runtime.
  • focus_sessions, vibe_checks, block_list: future focus/body-double/app-blocking substrate.
  • events: append-only behavioural history for future intelligence.

Gap Against The New POC

New POC definition: “A smart reminder app that knows enough about my life and location to remind me at the right moment, with AI helping create and adapt those reminders.”

Important Product Interpretation

“AI with context about your life” should not start as a chatbot. For this POC it should mean:

  1. It knows your saved places and common anchors.
  2. It can turn a messy sentence into a reminder draft with time/place/trigger.
  3. It can explain the trigger in plain language.
  4. It learns from reminder actions: done, later, dismissed, wrong place, no longer relevant.

That is much narrower than building a general companion. It is enough to prove whether Sidekick has a reason to exist.

Recommended Strip-Down Plan

POC thesis: “I can say or type a thing once, and Sidekick reminds me when the location/time context makes it actionable.” Everything else should be frozen until this loop works reliably on a real phone.

Keep

  • Flutter shell/theme: already useful and not the source of product sprawl.
  • Auth/profile/local-first DB: good foundation for personal context and offline use.
  • Sync, but keep expectations modest: useful if you use multiple devices, but the POC can work local-first first.
  • Places and reminders repositories: directly relevant.
  • Gemini transport and structured extraction: use it for reminder parsing, not broad capture decomposition.
  • Events log: keep only reminder and context events initially.
  • Native capture only if voice creation is core to your POC: otherwise allow typed reminder creation first to reduce risk.

Freeze Or Hide

  • Habits, Fresh Start, Done list: good work, but a second product.
  • Focus sessions and app blocking: high-complexity and not needed for reminder validation.
  • Goal Sage: keep the table if convenient, but hide goal UX and AI logic.
  • Auto-commit multi-item capture: useful later, but it complicates trust before reminders are proven.
  • Broad behavioural insights: do not build until reminder events accumulate.

POC Milestones

MilestoneDeliverableDone Means
1. Manual smart reminder A simple screen to create a reminder with title, place, enter/exit, dwell, optional time fallback. Reminder persists locally, survives restart, shows in a list, can be edited/deleted.
2. Geofence runtime Background location permission flow, geofence registration, enter/exit/dwell filtering, reboot/app-start restoration. Walk/drive into a saved place and receive one correct notification.
3. Notification actions Done, Later, Dismiss, Wrong place actions for reminder notifications. Actions update reminder state/events without opening the app.
4. AI reminder draft Text or voice input: “remind me to take the returns when I leave home” → structured reminder draft. AI proposes place/transition/copy; user confirms before activation.
5. Life context layer A small context service that passes profile, saved places, active reminders, recent reminder actions, and relevant tasks into the AI prompt. AI uses known places and prior feedback without inventing hidden assumptions.
6. Dogfood loop Use for 2 weeks; inspect reminder events and failed/wrong-place actions. You can answer whether the core concept helps in real life.

Possible Code Strategy

The cleanest path is not to delete everything immediately. Add a POC route/shell that only exposes Reminders and Settings, then stop wiring new code into habits/focus/inbox. This avoids churn while making the app mentally small again.

  1. Change bottom nav to Reminders and Settings for the POC branch.
  2. Add a features/reminders/presentation/reminders_screen.dart.
  3. Add place management inside reminder creation, not as a separate product surface at first.
  4. Add a ReminderScheduler interface with implementations for time notifications and geofences.
  5. Add ReminderAiDraftService that reuses Gemini transport but has its own tight prompt and schema.
  6. Add ReminderContextService that builds a bounded, explainable context object from profile, places, active reminders, and recent reminder events.

Risks And Decisions

RiskWhy It MattersDecision
Background location reliability Geofencing is platform- and OEM-sensitive. A smart reminder app fails if reminders do not fire. Make real-device geofence acceptance the POC gate. Do not proceed on simulator-only confidence.
AI overreach An AI that “knows your life” can make creepy or wrong assumptions. Use confirm-before-activate drafts. Show why a place/time was chosen. Learn only from explicit actions at first.
Client-side Gemini key The current app ships the Gemini key in the client build for personal use. Accept for private POC only. Before distribution, move Gemini behind an authenticated edge proxy.
Scope gravity Habits/focus/goals can keep pulling attention from the core POC. Hide them in navigation and stop adding tests/features there until the reminder loop works.
Missing source spec SIDEKICK_SPEC.md is absent, so requirements are reconstructed from the build plan and docs. Write a new one-page POC spec and make it the current source of truth.
Uncommitted changes The working tree contains modified and untracked files, including P5-related fixes. Stabilize or branch before larger cuts. Do not mix cleanup, P5 fixes, and POC pivot in one commit.

One-Page POC Spec Draft

Sidekick POC: A private, local-first Android app that creates reminders from plain language and fires them when time/place context makes them useful.

Must do: create/edit/delete location reminders; save named places; fire enter/exit/dwell notifications; support Done/Later/Dismiss/Wrong place; use AI to draft reminders from text/voice; keep a small context memory from places, profile, active reminders, and reminder feedback.

Must not do yet: habits, streaks, focus sessions, app blocking, monthly insights, broad goal planning, general chat, social features, multiple personas, iOS blocking, or complex analytics.

Success test: For two weeks, at least five real reminders fire at the right time/place, and wrong/missed reminders are explainable and fixable.
